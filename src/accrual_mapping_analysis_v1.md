# Accruals Mapping Analysis v1
## Scope
- Sample: 1,000 10-K filings / 100 firms / 2016–2025.
- Source analyzed: SEC Company Facts candidate facts generated by the project profiler.
- Candidate fact rows: 162,577.
- Unique XBRL concepts in inventory: 5,322.

This 36.0% number is NOT the final usable Accruals sample. Current-debt zero may sometimes be proven by reconciliation, and some missing mappings may be recoverable through additional XBRL concepts or controlled filing-level evidence.

## 2. Current debt mapping

### Current whitelist usage
Current-period filing contexts:
- LongTermDebtCurrent: 359
- DebtCurrent: 215
- ShortTermBorrowings: 207
- FinanceLeaseLiabilityCurrent: 178
- CommercialPaper: 120
- NotesPayableCurrent: 19

### Discovery concepts that materially expand coverage
Candidate concepts not in the original whitelist:
- LongTermDebtAndCapitalLeaseObligationsCurrent
- CapitalLeaseObligationsCurrent
- OtherLongTermDebtCurrent
- SecuredDebtCurrent
- NotesPayableRelatedPartiesClassifiedCurrent
- ConvertibleDebtCurrent
- NotesPayableToBankCurrent
- UnsecuredDebtCurrent

Using these as additional candidate concepts raises current-debt availability from 697/1,000 to 776/1,000 and prior-debt availability from 707/1,000 to 712/1,000.

### Important non-candidates
Do NOT treat the following as current debt simply because their names contain debt/lease/current:
- LongTermDebtAndCapitalLeaseObligationsIncludingCurrentMaturities
- DebtInstrumentCarryingAmount
- LongTermDebt
- DebtLongtermAndShorttermCombinedAmount
- future-payment schedule concepts such as OperatingLeasesFutureMinimumPaymentsDueCurrent
- generic operating-lease current liabilities

### Required hierarchy
1. Explicit aggregate current debt, e.g. DebtCurrent.
2. Aggregate current long-term debt/capital-lease concept, e.g. LongTermDebtAndCapitalLeaseObligationsCurrent, without adding components already included in it.
3. Otherwise combine non-overlapping current-debt families:
   - LT-current family: LongTermDebtCurrent / OtherLongTermDebtCurrent / SecuredDebtCurrent / ConvertibleDebtCurrent / CapitalLeaseObligationsCurrent (choose according to filing evidence and avoid overlaps).
   - Short-term family: ShortTermBorrowings OR CommercialPaper OR NotesPayableCurrent/related short-term notes, not all simultaneously.
4. If no debt-specific fact exists, allow a zero only through a documented current-liability reconciliation or filing-level evidence.

## 3. Taxes payable is the largest data bottleneck

Current+prior tax-payable candidate coverage is only 566/1,000.

Relevant target concepts:
- AccruedIncomeTaxesCurrent
- TaxesPayableCurrent

Discovery concepts found:
- AccruedIncomeTaxes
- AccruedIncomeTaxesNoncurrent
- TaxesPayableCurrentAndNoncurrent
- AccrualForTaxesOtherThanIncomeTaxesCurrent
- SalesAndExciseTaxPayableCurrent
- IncreaseDecreaseInAccruedIncomeTaxesPayable
- IncomeTaxesPayableCurrent / similar variants

Do NOT substitute flow concepts such as IncreaseDecreaseInAccruedIncomeTaxesPayable for a balance.

Do NOT automatically use TaxesPayableCurrentAndNoncurrent as current tax payable because it combines current and noncurrent amounts.

Among current-tax-missing filings:
- AccruedIncomeTaxes appeared in only 8 cases.
- AccruedIncomeTaxesNoncurrent appeared in 38 cases.
- TaxesPayableCurrentAndNoncurrent appeared in 17 cases.
- AccrualForTaxesOtherThanIncomeTaxesCurrent appeared in 26 cases.
- SalesAndExciseTaxPayableCurrent appeared in 13 cases.
- IncomeTaxesReceivable appeared in 51 cases.
No current-tax-missing filing in this candidate dataset had both AccruedIncomeTaxes and AccruedIncomeTaxesNoncurrent available together, so there is no broad, safe aggregate-minus-noncurrent rule to recover current tax payable from these fields.

For source alignment, the project methodology describes Sloan Accruals using the Compustat-style tax-payable variable. Therefore tax mapping should prioritize an income-tax-payable concept and treat broader taxes-payable concepts as an explicit adaptation only when the filing evidence supports it.

## 4. Special issuers

Persistent current-assets/current-liabilities absence across all 10 filings occurs for:
- ACGL
- DE
- KKR
- EXR
- O
- SPG
- VMRK
- WELL
- WRB

These are not one-off missing observations. They indicate issuer/business-model-specific XBRL presentation.

Therefore the final engine should NOT create a generic fallback like:
AssetsCurrent missing -> OtherAssets
LiabilitiesCurrent missing -> Liabilities

Instead, these issuers should be audited by economic structure. If the Sloan components cannot be defined consistently, the filing should remain WARN/excluded from the Accruals regression sample rather than receiving an invented value.

## 5. Depreciation

Current+prior candidate coverage: 956/1,000.

Current-period usage:
- DepreciationDepletionAndAmortization: 615
- Depreciation: 609
- DepreciationAndAmortization: 274

The project’s existing validated A 2016 case supports pure Depreciation = 95m rather than the broader 246m D&A value. Therefore the current implementation should keep pure depreciation as the source-aligned primary mapping unless the supplied methodology document explicitly instructs otherwise.

Combined D&A should remain a separate, auditable fallback rather than being silently relabeled pure depreciation.

## 6. Special note about prior fiscal year

All prior balance-sheet variables must use one common prior fiscal year-end.

A profiler fallback date should not be propagated automatically when an issuer lacks enough XBRL anchors. A date such as an old prior year can simply mean the profiler could not establish a newer prior year under its anchor rule.

## 7. Recommended final architecture

BALANCE ENGINE
- direct XBRL
- controlled alternatives
- one common prior fiscal end
- validation

DEBT ENGINE
- aggregate hierarchy
- component families
- overlap/double-count prevention
- zero only with evidence

TAX ENGINE
- income-tax-payable primary mapping
- controlled alternatives
- no flow variables
- no missing->0

SPECIAL-ISSUER ENGINE
- issuer-level mapping only where economically defensible
- otherwise WARN/exclude

VALIDATION
- source concept
- source accession
- source filed date
- current/prior period
- method
- quality
- warning reason

## 8. Decision

The SEC Company Facts data are rich enough to support a robust Accruals pipeline, but a single universal XBRL whitelist is not sufficient.

The next implementation should:
1. Expand current-debt candidates with the validated additional concepts above.
2. Build explicit non-overlap rules.
3. Treat tax payable as a separate strict engine.
4. Create an issuer-exception list for persistent non-standard balance-sheet structures.
5. Run a full batch only after these rules are implemented and audited.
